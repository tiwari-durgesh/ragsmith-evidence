### The question behind the prototype

Can evidence-sufficiency decisions preserve supported parts of an answer while
limiting unsupported claims? The proposed comparison concerns supported
requirement coverage and erroneous-answer risk. A precise lack of useful coverage
gain, or unacceptable unsupported-claim risk, would challenge the empirical
advantage. It would not be rescued by a polished demonstration.

### What has been registered

The repository contains a preregistration and subsequent amendments. The approved
Option C amendment accepts unresolved report overlap: company-name and content
hash checks **cannot establish disjointness**. Results under that scope can only
be descriptive. No claims of question independence, statistical superiority or
generalization to other documents are allowed. This app does not revise those
decisions. The public manifest records the registered document hashes.

### What the pilot establishes

The earlier pilot has **18 independent source facts and 36 derived cases; no
statistical or performance claims are made from it**. Labels are **provisional,
single-annotator**. The six cases here demonstrate software behavior using
existing controlled pilot tables. The conflict contains an artificial value.
The UI compares frozen extraction-only, binary and graded pilot policies; it
does not run the future fixed-model research comparison.

### What remains unproven

Real retrieval effectiveness, reliable risk/coverage improvements, confidence
calibration, genuine-conflict feasibility, broader table support and out-of-sample
generalization remain unproven. The implemented retriever is lexical FTS; the
proposed wider hybrid architecture is not established here. A model-independent
source reviewer and authorized research gates are still needed. This session
does not select data, calibrate, label or run a real evaluation.
